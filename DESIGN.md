# Tervia workspace

## Direction
A native, flat desktop workspace with a compact project rail, stable module navigation, and large readable working surfaces. No WebView.

## Layout
- Native macOS window controls in a 48-point unified titlebar, independent of the 56-point rail.
- The system menu bar groups workspace actions under File, View and Terminal, follows the interface language, and disables unavailable actions. Terminal output actions target the focused split pane; menu entries reuse the page controls' handlers.
- Project navigation always reserves 56 points in the layout. Hovering project search or a project immediately reveals a compact floating project list below module navigation; its rounded, opaque surface uses a neutral theme background, balanced 8-point insets and a restrained shadow, and grows only to the list height, capped by the available space. A compact header shows the project count, with search and pin actions; project icons remain aligned with the narrow rail. Local Terminal and the bottom tools stay in the narrow rail; neither temporary nor pinned expansion resizes the terminal or other content. Leaving the entire overlay for 150 ms collapses it, and reentry cancels the pending close. A pin beside project search keeps the overlay open, with its state persisted across restarts. The titlebar toggle and Cmd+B toggle pinning; Escape dismisses only temporary expansion. Project rows keep their vertical positions as the overlay opens. Rows are 40 points tall and switch directly to the project’s last working directory. Project roots never expand into filesystem children. The titlebar provides a compact project / working-directory button with a disclosure chevron. Its 320-point popover contains search, a virtualized flat directory list, a check on the current directory, and Add Working Directory below a separator. Discovered Git child repositories appear automatically alongside explicitly added directories, with the project root always available. Up/Down selects, Enter switches, Escape dismisses, and Cmd+Option+O (Ctrl+Alt+O elsewhere) opens the picker. Full paths remain in tooltips; long names truncate within the titlebar without displacing fixed actions. Native folder selection and Files folder menus provide the two directory-adding paths.
- Linked worktrees share one logical project and one repository-list entry, grouped by their common Git directory; independent clones remain separate. The project name stays stable while its branch follows the active directory, and the bottom status strip shows that directory's actual path.
- Terminal / Git / Files stay in the same top-row positions while projects change. Git and Files expose one bottom-terminal toggle beside the branch control. The optional dock shares the actual terminal entities with the full Terminal page, uses one native vertical resize handle and reserves readable space for both surfaces. Its toolbar offers close, sessions, split, search, clear and copy controls.
- Terminal: secondary session tabs with whole-tab hover, a native terminal cell grid with scrollback, shell-owned prompts/input/cursor, mouse selection and optional two-pane split. No separate command textbox.
- Git follows the Sourcetree / Fork workbench model: persistent navigation and branch sidebar; compact worktree/index file groups beside a native highlighted Diff; a commit section collapsed by default, retaining its draft and staged count; horizontal history table above commit details. File/Diff and history/detail dividers are draggable. Selecting a local branch, remote branch, or tag opens its reachable commit history and graph without changing the checkout. A clearly labeled Switch to This Branch action stays in the history toolbar, while merge, rebase, rename, and delete live in context and overflow menus. Double-clicking a branch performs checkout. Current-branch controls in the top module navigation and Git toolbar open one searchable picker at the clicked anchor; Cmd+Option+B / Ctrl+Alt+B opens the navigation control from any module. The picker marks the current branch, prioritizes up to eight recent branches per working context, supports Up/Down and Enter, and keeps selection by reference identity through refreshes. Local tracking branches are reused for remote targets. A failed checkout keeps the picker and existing diagnostic disclosure visible; success closes it and restores focus without switching modules. The branch/tag section Plus controls open small creation forms; rename uses the same form. Remote/stash management use flat rows. Working Copy separates tracked Unstaged, Untracked Changes and Staged, with Conflicts when present. Untracked Changes supports counts, group/folder folding, worktree Diff and per-file/group Stage; Stage all is scoped to its Unstaged or Untracked Changes group.
- History has a native commit-graph column with thin blue, lavender and amber tracks, aligned nodes and compact ref badges. Its layout is computed for the entire loaded history so virtual scrolling and pagination retain connections. Filtering leaves short dashed stubs and visible gaps around hidden rows. Commit details show the subject, SHA, author, date and navigable parents above a compact changed-file list and native Diff; full original metadata is available through a disclosure control. Merge diffs use the first parent.
- Git review provides Previous/Next File and Previous/Next Change controls. File navigation follows the visible tree order, including distinct worktree and index entries, and unfolds the destination group/folder. An Expand Diff control temporarily hides navigation/list panes, with Restore Layout returning to the previous split. Up to eight recently viewed documents retain their native scroll, folds and selection after a freshly read patch matches the retained document. Opening a full working file provides Back to Diff and restores the original comparison; selected modified lines position the file cursor.
- Git file rows use compact layouts with name, status and staging action; full paths remain available in tooltips. File folders, index/worktree groups, repository/branch/tag sections and stash lists can collapse, with state retained per project. Working-copy and sidebar sections preserve their original order when folded, showing only their fixed headers; all-folded sections remain at the top. Expanded sections fill the available height and scroll independently. Native horizontal dividers resize neighboring expanded sections while preserving collapsed header heights. Each project remembers section heights for the session; reopening restores the previous height, constrained by the current available space and readable sibling headers. Sidebar navigation stays fixed above its sections, and the commit control stays below the working-copy sections. In compact windows the commit form scrolls while section and commit headers remain visible. Section seams paint one hairline; resize handles retain their hover indicator and drag band. Collapse-header hover fills the entire row, and section counts have an 8-point internal right inset.
- Git's collapsible Worktrees section sits below its navigation and above branches. Compact 32-point rows identify branches or detached directories, mark the current directory with a check, and show locks or missing-directory states; full paths remain in tooltips. The section's Plus control opens management.
- Worktree management keeps three checkout choices (New Branch, Existing Branch, Detached HEAD), the destination with a native path chooser, applicable branch/start-reference fields, and Create above a virtualized directory list. Flat 52-point directory rows show the branch or detached label above a quieter path; selection uses the existing translucent blue tint. A single toolbar acts on the selected directory, and its optional lock reason sits below the list. The form, toolbar and rows reveal the continuous shell gradient in both themes.
- Files: the selected directory’s contents begin directly below the explorer toolbar, beside a native code editor with syntax highlighting. The window titlebar identifies the current directory; the explorer does not repeat it as a root row. The tree loads one directory at a time on background workers and virtualizes visible rows; it hides `.git` and does not expand directory symlinks. Directory expansion and scroll position remain independent per project.
- Opened files occupy a horizontal tab strip above breadcrumbs and the editor. The upper-right breadcrumb actions place a compact Refresh icon beside Find and Save; disk-change notices appear only in context, with no permanent Reload strip. A native file chooser remains available.
- Bottom status strip communicates project, branch, focus context, and live Git context.

## Visual system
- User-pinned visual reference: a restrained gray-blue gradient inside the application window, brighter at the upper left and darker at the lower right. The outer red showcase background is excluded.
- The application shell and terminal retain the native GPUI gradient #515764 → #20212C. Terminal output stays continuous, with no command/output grouping. Every Git pane, sidebar, toolbar and Diff reveals that same continuous window-sized gradient. Selection and hover use translucent overlays; no pane paints an opaque canvas. Git uses #98BEE8 / #2E67A3 focus accents in dark / light mode.
- Light mode uses a visible native gradient #F3F5F8 → #CED8E7, from pale gray to cool gray-blue. Secondary text and semantic accents are darker to remain readable at the darker endpoint.
- One window-sized background owns the shell gradient. Project, module and terminal session selections use a translucent neutral fill. Git pane boundaries use quiet separators for scanability; file and branch selections use a translucent blue tint. Semantic diff highlights retain their green and red fills.
- Additional themes preserve the continuous gradient and semantic roles: Midnight uses cool navy, Forest uses deep green, Paper uses warm ivory and amber, and Rose uses pale pink and berry. Each preset supplies solid auxiliary surfaces, readable ink, selection and focus accents; its light/dark base also controls syntax highlighting and icon variants. Dark and light modes each remember their own preset; the titlebar action toggles the two remembered choices and makes that appearance explicit. System mode follows live OS appearance changes using the same remembered presets.
- Primary text #E6E8EC, secondary #C0C6D0, quieter text #A4ACBA.
- Shell and editor focus use soft mint #A8D9C5; Git ref/action accents use restrained blue. Semantic green/red are reserved for changes and diff lines.
- System sans for UI, Menlo / SF Mono for terminal and code. UI 13–14 points, code 14 points with generous line height.
- The shell cursor defaults to a blinking narrow beam aligned to text height; terminal programs may request block, underline or hidden cursor shapes.
- Icons from GPUI Kit's Lucide set; project avatars use restrained initials and authored geometric marks.
- Tervia's application logo is a flat geometric T made from two mint shapes separated by a diagonal cut, on a solid graphite tile. `assets/tervia.svg` supplies the welcome screen, Linux icon, and macOS icon generation; `assets/tervia.ico` is the Windows export. The tile and silhouette remain consistent across themes.
- Flat regions and separators; no nested cards, decorative gradients, or ornamental shadows.
- Preference edits open a separate 760×640 native desktop window (minimum 700×580). A 176-point sidebar groups settings into General (language and startup), Appearance (themes, interface size and terminal/code typography), Workspace (file, terminal and agent behavior), and Online Updates. General opens by default. The configuration-file entry stays at the sidebar bottom. The right pane uses 24-point side insets, 44-point rows and a shared 224-point control column. Appearance uses Dark / Light / System segments. Two independent three-column lists show eleven native themes as borderless 44-point option rows, with a fixed 56×36 landscape thumbnail beside a readable name and a reserved check slot; long names can wrap to two lines in narrow windows: Dark / Midnight / Forest / Darcula / Monokai / Solarized Dark and Light / Paper / Rose / Solarized Light / Quiet Light. Incomplete rows retain full-size previews; the existing form scrolls to reach all choices. Classic presets supply distinct syntax and terminal ANSI palettes with readable UI inks. Thumbnails use the actual palette, syntax colors and gradient. A quiet neutral fill and check identify each remembered choice. The explanation of independent choices is available in the appearance controls’ tooltips. Selecting a preset changes only its own mode; inactive-mode edits do not switch the appearance; dropdowns have explicit outer bounds; font sizes use compact steppers. A short type specimen follows code typography settings. The fixed footer contains a Reset for the current category and save/error status while only the form body scrolls; reselecting or switching categories returns the form to the top. Each category resets only its own preferences. Appearance reset preserves language and workspace behavior; General reset preserves themes and typography; Workspace reset preserves appearance. All resets preserve system startup state, command-history recording choices, agent notification consent and update policy. A shared preference entity updates the workspace immediately and persists to TOML.
- Custom themes share the existing three-column appearance lists and actual-color thumbnails. Create theme copies the current choice; context menus offer Duplicate and edit, plus Edit and rename and Delete theme for user themes. A separate 960×680 native editor (minimum 880×600) uses stable chrome, a 364-point color column with Interface / Code / Terminal tabs, and an isolated synthetic workspace preview. Color rows pair a native picker, HEX input and Restore original color; auxiliary colors and ANSI colors expand progressively. A fixed footer shows validation/contrast feedback and Cancel / Save and use. Editing never changes the workspace before a successful save; save selects only its matching appearance and preserves the other choice and System mode. Dirty closing requires discard confirmation.
- Settings and auxiliary windows use solid theme backgrounds. The welcome screen uses the continuous window gradient, a brand/introduction column and an action column: two 76-point rows offer Open Project and Use Terminal with icons, secondary descriptions and keyboard hints. Recent projects sit below a quiet separator. Clone Repository opens a compact form with a persistent repository-address label, an example address, Choose Destination, and a short explanation that cloning opens the result. The destination name follows the repository address.
- Settings use a transparent 48-point draggable titlebar with native traffic lights. The current category appears once as a 16-point semibold title aligned with the right pane's 24-point content inset; the form starts directly with its controls. The sidebar background and its quiet divider continue to the window's top edge, keeping the sidebar and content as two continuous solid surfaces.

## Interaction
- Cmd+Option+P / Ctrl+Alt+P and sidebar Search open a global project switcher. Its 520-point native surface has a focused input, virtualized 52-point name/path rows, bounded list height, closed-state labels and an optional Back to Previous Project action. Up/Down navigates, Enter selects and Escape or clicking outside restores prior focus. The same surface provides recently closed mode from the File menu, sidebar footer and welcome screen.
- Project favorites use a compact star control in expanded rows and a small star in the icon rail. Favorites sort above ordinary projects; dragging within a group shows a thin drop cue and changes only presentation order. Move Up/Down context actions provide keyboard-accessible ordering. Recent visits never reshuffle the sidebar.
- Close Project names the project path and affected terminal count, keeps drafts/layout and stops only owned sessions after persistence succeeds. Reopen validates the captured directory and rejects stale results. Closing the last project returns to existing local sessions or to the welcome screen with a recently closed entry point. Local terminal processes are never owned by a project.
- Cmd+B toggles the project rail; Cmd+1/2/3 switches module; Cmd+S saves the current file to disk.
- Cmd-click / Ctrl-click terminal file references opens their project-local source location; the pointer indicates recognized references while the modifier is held. Ordinary terminal selection and mouse reporting remain intact.
- Files source and Git Diff expose Copy Context beside their existing tools, with Cmd/Ctrl+Shift+C and a File-menu action. No selection disables the toolbar action; Files copies the current draft and Diff preserves the selected version and source line numbers. Pressing the Diff action captures its selection for that gesture because native text selection clears before the click callback; cancellation or a new patch discards it.
- Cmd+K on macOS (Ctrl+Shift+K on Windows/Linux) clears the focused terminal's viewport and scrollback, then sends Ctrl+L to request a redraw. Ctrl+K remains a terminal-program keystroke.
- Esc goes to the shell/application while the terminal has focus. Otherwise it dismisses the current menu or quick-actions overlay first, then closes the current window. Closing Settings returns to the workspace; closing the sole workspace exits and terminates its owned PTYs.
- Switching projects or modules retains state and never clears terminal history or unsaved drafts.
- All scrollable work surfaces use thin native GPUI overlay scrollbars, revealed while scrolling or dragging and fading after roughly two seconds of inactivity. Dragging a terminal selection above or below its pane keeps scrolling and extending the selection until the pointer returns or the button is released; focus loss cancels the gesture.
- Every working directory retains independent terminal sessions, module selection, file tabs, drafts, Files expansion/scroll, and Git inputs and selections, including ordinary directories sharing one Git identity. Opening another Worktree changes the active directory without adding another repository. Sidebar project selection restores its last directory, while the titlebar picker changes the directory within that project. Later project or module selection supersedes a pending directory validation. Explicitly added directories survive restart; Git child repositories refresh in the picker after each scan without becoming permanently saved manual entries.
- Worktree creation supports a new branch from a start reference, an existing local branch, or detached HEAD from a revision. An initial commit is required; missing inputs and busy operations disable creation, while failures use the existing Git error/status area. Bare or missing directories cannot be opened.
- Lock and Unlock act on the selected linked directory and preserve an optional lock reason. Remove names its full target path in a native confirmation, retains the branch, and protects main, current and locked directories. Git changes and unsaved drafts block removal; files opened through an enclosing folder must be closed before removing its child Worktree. Only successful removal stops that directory's terminals and monitoring, with unrelated sessions and drafts retained.
- Prune names the repository and exact missing-directory registrations in its confirmation, then rechecks those captured records before removing metadata. Locked registrations are excluded; changed targets require a refresh. Worktree actions expose no force removal, branch deletion, move or repair.
- Native file monitoring covers visited directories and opened files, pauses when the workspace deactivates, and starts an immediate refresh on foreground activation before normal monitoring resumes. Clean buffers synchronize with disk; dirty drafts retain their text and show a contextual disk-change notice.
- File tabs provide an X close control, middle-click close, and a contextual menu for Close, Close Others, Close to the Right, Close All, and Reopen Closed Tab. The strip scrolls horizontally when tabs overflow and supports drag reordering. Ctrl+Tab / Ctrl+Shift+Tab cycles files; Cmd+W / Ctrl+W closes the current file, and Cmd+Shift+T / Ctrl+Shift+T reopens the last closed tab.
- Closing dirty files asks once for the whole close operation, with Cancel, Don't Save, and Save and Close. A failed save or new typing during the save keeps the tabs open.
- Git and file actions operate on the selected real directory. Background requests retain their originating project and reject stale results; consequential actions name their target in a native confirmation. Terminal commands run on the actual machine, including the user's shell plugins.
- Loading, errors, non-repository folders and empty file views have explicit states. Startup restores the last project, local terminal or welcome screen, without an implicit project. Local Terminal is fixed above the sidebar project group, with a Start entry in the footer. Its titlebar offers Open Project; its content starts directly with terminal tabs, without a redundant module navigation row. Cmd+Shift+N / Ctrl+Shift+N creates a local session; Cmd+T / Ctrl+Shift+T enters a terminal directly from welcome. Git selects the first real change or commit on entry; an existing explicit selection is preserved until its target disappears. Background refresh never inserts or removes a loading row while reviewing a Diff.
- Interface language follows the OS preferred-language order by default; Settings provides ten language choices plus System. Changes update app chrome, menu labels, placeholders and notices without translating terminal output, paths or user content.
- On macOS, terminal tabs use Claude / Codex / Gemini / Grok / Hermes / OpenCode / OpenClaw brand glyphs and names while their executables are in the PTY foreground process group. Returning to Shell restores the terminal glyph; terminal conversation text never determines identity.
- Shared icon controls are transparent at rest and use neutral text-color overlays at 0.12 alpha on hover and 0.20 alpha when pressed, inside the whole-tab or whole-row hover. Disabled action states remain intact. Group staging Plus / Minus controls keep their tooltips and accessibility names.

- Terminal search opens a 40-point native query bar inside its pane, with match position/count, previous/next and close. Query-field Enter/Shift+Enter/Escape never reach the PTY. Search highlights the active match and reveals scrollback without replacing output. Unread terminal bells add a compact trailing bell to the session and an accessible dot to its logical project, preserving agent branding.
- Git working-copy headers show reviewed progress; each file Diff offers Mark Reviewed/Reviewed. Changing source or its index/HEAD comparison base invalidates its marker after refresh. Set Checkpoint captures disk content using a private index; Compare Checkpoint opens a focused native Diff with refresh and Back to Working Copy. Checkpoint comparisons expose no staging actions.
- Workspace recovery records module/dock, shell tabs, opened files and source reading positions. Clean sources reload asynchronously without changing selection; recovered draft/base pairs remain protected by normal disk conflict checks. Changes coalesce over 300 ms; project navigation and quitting flush immediately.

## File browsing
- Common file types use 16-point Material Icon Theme glyphs, shared by the file tree, file tabs and their drag preview, editor breadcrumbs and filename/text search results. Preserve upstream colors and available light-theme variants; keep folder and symlink glyphs in the existing native style. Specific filenames take precedence over compound suffixes and generic extensions; unknown files use the generic document glyph.
- Git-ignored filenames, file/folder icons and directory disclosures use subdued neutral ink in both themes. Selected filenames keep the normal readable foreground while icons remain subdued. Selection backgrounds, hover, draft indicators and file-opening actions retain their existing behavior.
- Single-click opens one italic preview tab per directory. Another clean preview replaces it in place; double-click or editing pins it. Existing pinned tabs and dirty drafts remain open.
- Optional related-file nesting starts companion groups collapsed beneath existing parents in the same directory. The disclosure arrow expands or collapses the group; filenames retain single-click preview and double-click pinning. Nested rows keep the existing native 30-point layout and theme.
- Quick Find File (Cmd+P, Ctrl+P on the Files page) and project text search (Cmd/Ctrl+Shift+F) share the native explorer sidebar. Results are virtualized, keyboard-selectable, and retain project ownership. Enter opens the selected file; text matches open pinned source at their line and column. Escape returns to the tree.
- Markdown opens in a native reading view with Source/Read switching; draft content drives the preview. Project-local images can appear inline. PNG, JPEG, GIF, WebP, SVG, BMP, TIFF and ICO open in a native fit-to-pane image viewer, with reload and load-error fallback. Images remain read-only and use the existing 4 MiB file-read limit.
- Searches respect ignore files, skip dependency/build directories, images and binary/non-UTF-8 files, and never follow symlinks. Scans stop after three seconds or 50,000 files; text search returns at most 1,000 matches with a 128 MiB read budget, and filename results at most 500. Any truncation or unreadable text file is reported. Superseded queries cannot install stale results.
