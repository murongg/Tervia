# Tervia

<!-- impeccable:product-schema 1 -->

## Platform
Native desktop, with macOS as the primary review platform and Windows / Linux platform adapters and build scripts. No WebView or browser runtime.

## Stack
Rust + GPUI. GPUI Kit supplies native text editing and controls.

## Product Purpose
Bring terminal use, Git review, file navigation, and small code edits into one workspace.

## Capabilities and Constraints
- The left project sidebar always reserves a 56 logical-pixel icon rail. Hovering project search or a project immediately reveals a compact flat project list over the workspace, below module navigation and capped by the available height, without resizing terminals or other content; leaving for 150 ms collapses it. A pin control keeps the overlay open across restarts, while temporary hover expansion is never saved. The titlebar toggle and Cmd/Ctrl+B toggle pinning; Escape dismisses a temporary expansion. Clicking a project restores its last working directory. Working directories switch from a searchable titlebar popover.
- A global keyboard-driven project switcher searches names, paths and fuzzy abbreviations, including known working directories/worktrees. Empty searches rank favorites and recent projects; Back to Previous Project restores the prior project's last directory. Favorites stay above ordinary projects in the stable sidebar, with persisted drag ordering within each group and Move Up/Down menu alternatives.
- Closing a logical project preserves all of its directory drafts/layout in workspace recovery before ending its owned terminals with a named confirmation. Failed persistence or active Git/file writes prevent closing. Closed projects remain searchable and reopenable across restarts; the welcome screen exposes Recently Closed Projects when all projects are closed. Reopening validates the directory, respects later navigation and creates new shells on demand. The project menu also copies its root path and reveals it in the system file manager.
- Project workspaces have three fixed tabs: Terminal, Git, and Files. A permanent Local Terminal entry above the project list owns separate shell tabs and split state, starts in the user home directory, and never registers or scans that directory as a project. Local sessions survive project switches and project closing; the final local tab can be explicitly closed to an empty terminal surface.
- Each project retains its current tab, terminal sessions, file selection, and in-memory changes.
- Terminal sessions now run the user's real login/interactive shell over a PTY, with native GPUI rendering backed by alacritty_terminal. Commands execute normally and the shell loads the user's existing configuration.
- Run Task in the project navigation, Terminal menu, or Cmd/Ctrl+Shift+R opens a searchable, keyboard-driven native task picker. Discovery reads package.json, Cargo.toml, Makefile/GNUmakefile, case-insensitive justfile/.justfile, and version 3 Taskfile YAML variants in the selected working directory. It never invokes task runners or project code during scanning, and reports malformed, oversized, ambiguous or partially supported sources while retaining tasks from other sources. packageManager selects npm/pnpm/yarn/bun, otherwise one lockfile family selects it, falling back to npm when none exists. Cargo offers build/check/test and explicit or main binary run targets, including their required features. Make reads literal targets and .PHONY declarations without evaluating macros, conditionals or includes. Just exposes public recipes with no required arguments and resolved aliases, respecting platform attributes; required/advanced arguments and imports/modules report partial discovery. Taskfile reads YAML task declarations, aliases and bounded anchors/merges, hides internal/dynamic tasks, leaves required-variable validation to Task at runtime, and reports unexpanded includes. Commands bind the exact selected task file. A task starts in a new owned terminal using the configured shell, preserving existing sessions and the exact working directory. The terminal shows its command and lifecycle/exit result; Rerun is available after exit or a failed launch and creates another terminal while retaining prior output. Task identity and completed output survive UI restart; recovery reconnects or replays without running the task again. Discovery is limited to 1 MiB per manifest, 8,192 directory entries for filename matching and 256 displayed tasks. Unsupported shells and script names CMD cannot safely quote report an error.
- Startup restores the last screen (project, local terminal, or welcome), the project list, order, selection and sidebar expansion. First launch offers Open Project and Use Terminal, recent projects and a secondary clone action. An unavailable last project falls back to welcome; legacy history remains readable. Projects are actual directories; terminal sessions start in their directory. Terminal processes are owned by detached local hosts and survive UI exit, reopen and app updates. Persisted connection identities reconnect to the same PTY; historical output and resize events replay before live input is enabled. Explicit tab/project/worktree closing terminates only the owned sessions. Unavailable hosts are reported instead of silently launching replacement shells. Module selection, bottom-terminal layout, shell-tab count/selection, open-file order, source cursor/scroll positions and unsaved drafts recover from workspace history. Clean files load from disk asynchronously; changed disk content cannot overwrite a recovered draft.
- Opening a folder creates one workspace root and initially selects that folder. The sidebar lists only project roots. The titlebar shows the project and current working directory, and opens a searchable flat list containing the root, automatically discovered Git child repositories, and explicitly added directories. Add Working Directory uses a native folder chooser scoped to that project; Files folder menus offer Set as Working Directory. Ordinary subfolders appear only after explicit selection. Each working directory retains independent terminals, files, drafts, Git inputs and module selection. Workspace history remembers added directories and the last selection, skipping missing directories on restart. Git discovery remains bounded and populates the working-directory picker without adding sidebar projects; automatic results refresh independently of saved manual directories.
- Long Git lists are virtualized; folder and section folding is retained per project.
- Selecting a Git branch or tag opens its own paginated history and commit graph without changing HEAD or working files. Double-clicking a branch performs checkout, while single-clicking remains browsing. A searchable branch picker in the top navigation and Git toolbar, plus Cmd+Option+B / Ctrl+Alt+B, supports recent-first ordering and stable keyboard selection without changing modules. Remote refs reuse existing local tracking branches. Checkout errors remain visible in the picker; branch/tag operations use contextual menus and compact creation/rename forms. Scope changes reject stale history results, while refreshes preserve the selected branch and history queries use fully qualified refs.
- Git review defaults to a collapsed commit form, with an expandable Diff, file/change navigation and a return path from full-file inspection. Recent comparisons retain their native reading state only when a freshly loaded patch is unchanged.
- Git uses the system CLI on background workers: changes, file/hunk staging, commits/amend, history, branches/tags, remotes and synchronization, stash, merge/rebase and conflict recovery.
- Linked worktrees belong to one logical project, identified by the shared Git directory. Its project entry restores the last working directory while each directory retains independent terminals, file tabs, drafts and Git state. A collapsible Worktrees section and management view support opening, creation from new/existing branches or detached HEAD, lock/unlock, safe removal and pruning missing registrations. Removal retains branches, rejects unsaved drafts and Git changes, and stops only affected terminals after success; force removal is not exposed.
- The file editor opens real UTF-8 files and saves to disk. External disk changes, newer reads and newly typed drafts cannot silently be replaced by older results.
- File browsing supports one replaceable preview tab, pinning by double-click/editing, background fuzzy filename search, literal project text search with source jumps, native Markdown reading/source views, and read-only image previews. Search honors project ignores and explicitly reports limits.
- Common file types use bundled Material Icon Theme SVGs consistently across the file tree, file tabs and search results. Project filenames and TypeScript declaration suffixes receive specific icons; unknown files use a generic document. Folder icons retain the existing style and ignored file icons remain subdued.
- Settings → Interface → File list → Nest related files defaults off (`[files] nesting = false`); changes apply globally and immediately and persist in TOML. Enabling it groups same-directory companions under existing `.env`, `Dockerfile`, `package.json`, `Cargo.toml` and common source/test parents, preserving real file paths and lazy directory loading. Rules are bundled, with no custom rule editor or automatic upstream updates.
- Files shows the selected project’s directory tree, with lazy directory loading, virtualized rows, folding and automatic filesystem monitoring. Expansion and opened document drafts are kept independently per project. The tree hides Git metadata and does not recurse through directory symlinks. Native monitoring pauses when the workspace loses foreground activation and performs an immediate refresh before resuming when activated. It covers visited directories and opened files without recursively subscribing to dependency trees. Clean buffers synchronize automatically; dirty drafts are preserved with a disk-change notice. Manual file refresh is a compact icon beside Find and Save.
- Git-ignored files and folders remain browsable, with subdued filenames and icons in both themes. Directory reads batch Git ignore checks in the background, respecting nested repositories, negated patterns and tracked files; unavailable Git never blocks browsing.
- Preferences persist in a user-editable TOML file, organized by feature domain (`ui` and `ui.fonts` today). Settings changes save immediately; manual edits apply on restart. Comments, unknown settings and dotfile symlinks are preserved, and invalid files or external edits are never silently overwritten. Project history saves independently in `workspace.json` beside the configuration file, remembering the last worktree directory with a main-directory fallback.
- Native macOS verification covers both themes, continuous window gradient, full-row header hover, count insets, multiple nested repositories, virtual scrolling/folding, staging/commit and conflict editing/resolution/continuation with synthetic repositories.
- Interface text supports ten languages and defaults to the system's preferred supported language.
- Agent tabs identify supported CLI entrypoints using background process inspection; Hermes uses the official monochrome mark with theme-aware contrast.
- Terminal file references open the current project's source with Cmd-click / Ctrl-click, using project-relative or project-contained absolute paths and optional one-based line/column suffixes. Resolution and file reads run in the background; later navigation wins and dirty drafts remain intact.
- Files and Git Diff offer Copy Context and Cmd/Ctrl+Shift+C for selected source with relative paths and inclusive line numbers. File context uses the current editor draft; Diff context retains displayed original/modified source, renamed side paths, partial text selections and gaps between patch fragments. A Diff copy gesture holds its source only between press and release, with cancellation and patch changes clearing it.

- Git and Files can keep the existing terminal sessions in an optional adjustable bottom dock. New/split/close actions retain the document module; Cmd+J / Ctrl+Shift+J and a navigation control toggle the dock.
- Terminal Find searches literal rendered text and scrollback with smart case, native query input, Enter/Shift+Enter match navigation and Escape to return focus to the shell. Explicit background terminal bells flag the session and logical project until that pane is focused. Claude Code and Codex can additionally report precise lifecycle state through opt-in command hooks: ready, working, approval/input requests, response end, interruption, supported response failures and session end. No state is inferred from conversation content or output silence. Settings → Workspace installs/removes only Tervia's hook handlers while preserving existing CLI configuration, and exposes a persisted desktop notification switch that defaults off. Codex hooks require explicit /hooks trust. Hooks return an empty successful decision and only retain normalized state in the owned terminal directory, never prompts, tool input or transcripts. Background system notifications show generic status/project/tab labels and route by live console entity identity. Focus acknowledges attention; restoring prior state never sends historical alerts. The UI must remain running for desktop notification delivery.
- Working-copy review marks are bound to current source/index/HEAD versions and invalidated by refreshed fingerprints. Manual checkpoints use a temporary index and Git trees, include untracked files while respecting Git ignore rules, retain the real staging area, and compare a requested disk snapshot against the captured baseline. Marks/checkpoints belong to the current run.

## Brand Commitments
Tervia. Quiet, compact, readable developer tooling.

## Open Decisions
Live terminal sessions, including AI conversations still running in their PTY, survive UI exit and app updates. OS reboot/session-host termination cannot preserve those processes. Advanced history editing, hosting-provider APIs, and extended terminal protocols are future work. Windows GUI behavior and Linux desktop interactions still require hands-on platform validation.
